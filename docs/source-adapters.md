## Common contract, different adapters

An adapter should return approved metadata or results with a stable source reference, permitted destination, source version, observation time, and authorization validity. Unsupported or missing metadata stays unknown. It should not fabricate a uniform capability across vendors: viewing, export, querying, and indexing are distinct operations.

Warehouse/lakehouse adapters execute governed analysis rather than treating tables as documents or iframe destinations. Knowledge adapters retrieve permitted, versioned content. BI adapters retain native viewing behavior and separate semantic access. A native-open fallback preserves supported functionality when embedding is unsuitable; embedding never grants the intelligence layer access to report contents.

Optional search services need their own access assessment. [Cortex Search](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-search/cortex-search-overview) uses owner's rights. [Azure AI Search's native ACL/SharePoint approaches](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview) are preview and depend on synchronized permission metadata. Neither is an implemented dependency, and neither automatically establishes end-user policy preservation across these six sources.

Before connecting any target, validate execution identity, data policies, embedding/license limits, synchronization and revocation, query limits, citation destinations, and source completeness against the chosen tenant/deployment. The [roadmap](validation-and-roadmap.md) records these future integration gates.
