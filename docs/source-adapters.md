## Report interaction

**Power BI design:** use authenticated internal-user organization embedding with JavaScript SDK integration. Users retain report access requirements. The organization tutorial describes Pro/PPU configurations or qualifying capacity at least equivalent to F64 for free viewers; validate the actual workspace and content license combination. The simple secure Website/portal iframe is a separate option: its automatic authentication does not work with the JavaScript SDK. Never use public Publish to web for confidential content. [Organization prerequisites](https://learn.microsoft.com/en-us/power-bi/developer/embedded/embed-sample-for-your-organization), [secure iframe limits](https://learn.microsoft.com/en-us/power-bi/collaborate-share/service-embed-secure).

Supported APIs include report/page/visual [filters](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/control-report-filters), [page navigation](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/page-navigation), [slicer state](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/control-report-slicers), and [report settings](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/configure-report-settings). Wait for loading before issuing commands. Hierarchy slicers require SDK 2.21 or later; tuple slicers are unsupported. Report features, author choices, permissions, SDK version, and tenant settings constrain functions. Host theme/navigation/panels do not confer unlimited styling, editing, subscriptions, or workspace administration inside an embed. Filters do not replace source authorization.

**Looker design:** private embedding keeps authenticated access to supported content. Custom themes require instance enablement. Signed embedding is an alternative authentication design: Google Cloud core requires Embed edition; Looker original requires feature enablement. It needs carefully scoped identities, permissions, models, and server-side signing. Confirm instance network/browser-session requirements. SDK 2 supports host communication and navigation; its API is separate from the server Looker API. **Looker and Looker Studio are different products**; no interchangeable API or embed contract is assumed. [Private embedding](https://docs.cloud.google.com/looker/docs/private-embedding), [signed prerequisites](https://docs.cloud.google.com/looker/docs/signed-embedding), [SDK](https://docs.cloud.google.com/looker/docs/embed-sdk-intro).

## Query execution

**Snowflake:** SQL API authentication includes OAuth and key-pair approaches; choose an execution identity that preserves end-user entitlements. Explicit role, warehouse, database/schema, typed bindings, and timeout belong in the adapter's approved request, not arbitrary browser claims. Submission supports asynchronous execution/status handles, partition retrieval, cancellation, and request-ID retry controls. The API can execute DDL/DML: read-only templates, least privileges, query/resource budgets, row limits, concurrency limits, and safe retry handling are application requirements. Query success is not proof of upstream close completeness. [Authentication](https://docs.snowflake.com/en/developer-guide/sql-api/authenticating), [request/status/cancel reference](https://docs.snowflake.com/en/developer-guide/sql-api/reference), [row policies and edition](https://docs.snowflake.com/en/user-guide/security-row-intro).

**Databricks:** the AWS Statement Execution documentation describes named typed parameters, warehouse/object permissions, async status, chunks, row/byte limits, truncation, and cancellation. A wait timeout normally allows execution to continue; cancellation requires the appropriate setting or request. Preserve pending, running, succeeded, failed, canceled, and closed states rather than treating a successful HTTP response as complete data. Protect EXTERNAL_LINKS presigned URLs as credentials and omit Databricks authorization headers when retrieving their storage objects. This is SQL execution, not the full workspace/notebook UI. Cloud, warehouse type, identity configuration, and Unity Catalog policies must be verified in a tenant. [Statement Execution tutorial](https://docs.databricks.com/aws/en/dev-tools/sql-execution-tutorial).

The local [query session](../examples/governed-query.mjs) demonstrates lifecycle and bounded results against synthetic records, without SQL-engine compatibility. A production adapter still needs source-specific retry reconciliation, budgets, secure pagination, cancellation confirmation, and source policy tests.

## Documentation rendering

Confluence Cloud v2 scopes do not erase page restrictions; direct API access uses the authenticated user's permissions. Retain page version, source, and cursor coverage. SharePoint Graph sitePage retrieval documents Sites.Read.All for delegated work/school or application access and optional canvasLayout expansion. Neither API promises complete native-site reproduction. The proposed renderer sanitizes supported content, authorizes attachments/links separately, and uses native opening for unsupported macros, web parts, or editing. No sanitizer or document UI is implemented in this release. [Confluence authorization](https://developer.atlassian.com/cloud/confluence/rest/v2/intro/), [Graph sitePage](https://learn.microsoft.com/en-us/graph/api/sitepage-get?view=graph-rest-1.0).

## Instrumentation coverage

| Coverage class | Examples | What remains unknown |
| --- | --- | --- |
| Fully observed host action, when instrumented | Search result shown, saved resource, query page displayed | User understanding or subsequent offline work |
| Supported embed event | Power BI loaded/rendered/pageChanged/error; Looker dashboard run/filter events | Unsupported interactions and unprojected payload content |
| Server outcome | Query complete/failed/cancelled | Whether the employee saw or understood a result |
| Proxy/inference | Matched search-to-render elapsed time | Task completion, causality, productivity |
| Unobservable here | Native-source activity after handoff; unsupported embed interactions | Usage volume; unsupported is not zero |

[Exact event mappings and privacy projection](journey-telemetry.md) define the small simulated subset. Power BI rendering may recur; Looker run completion is not proof every tile succeeded. [Power BI events](https://learn.microsoft.com/en-us/javascript/api/overview/powerbi/handle-events), [Looker events](https://docs.cloud.google.com/looker/docs/embedded-javascript-events).

## Unresolved production decisions

Before connecting any tenant, verify content/license combinations, identity delegation, source row/column controls, embed CSP/origins and browser behavior, API rate/resource limits, result freshness, and permission revocation. Validate document fidelity and accessibility against permitted test content. Confirm telemetry coverage and privacy approval per deployment. These are integration gates, not blockers for the completed local reference.
